# 《基于 Python Web 的本地文献综述工作台设计与实现》产品需求文档

## 1. 文档目的
本文档用于明确系统的产品定位、目标用户、界面功能设计、任务流设计、功能清单、优先级划分及验收标准，作为后续系统设计、页面设计、开发实现和课程报告撰写的依据。

## 2. 产品定位
本系统是一个面向科研综述写作场景的本地 Web 工作台，其本质不是独立重做一个新的大模型系统，而是基于 Codex 能力构建一个“为科研写作而生”的专用软件外壳。

系统的核心特点如下：

- 以 Codex 作为底层 AI 执行内核
- 以 Web 界面作为主要交互入口
- 以研究主题项目作为工作组织单位
- 以本地目录作为受控工作空间
- 以预设任务流和内置 skill 约束 AI 的工作边界
- 以结构化结果沉淀替代一次性聊天输出

## 3. 目标用户

### 3.1 主要用户
- 研究生开题报告写作者
- 综述类论文写作者
- 需要围绕某一研究主题进行文献收集、研读、整理与写作准备的个人研究者

### 3.2 用户特征
- 已有明确或初步明确的研究主题
- 希望通过一个统一界面完成文献检索、研读和综述写作准备
- 不满足于通用 AI 聊天，希望系统能够直接服务科研任务
- 希望 AI 能力被固定流程封装，而不是每次重新组织 prompt

## 4. 产品设计原则
- 聚焦科研综述场景，不做通用聊天产品
- 保留对话交互，但对话必须服务具体科研任务
- 页面结构围绕任务流组织，而不是围绕模型能力组织
- 所有核心结果都应可保存、可追踪、可再次利用
- 界面保持简洁，去掉与当前项目无关的入口和信息干扰

## 5. 界面设计需求

### 5.1 总体界面方向
系统界面参考 LitLit 一类科研工作台产品，但需要做减法设计，形成更聚焦的本地科研写作工作台。

### 5.2 首页导航保留项
- 新建项目
- 项目列表
- 文献检索
- 论文研读
- 综述写作
- 历史任务记录

### 5.3 首页导航删除项
- 与当前课程项目无关的推荐内容
- 与主题项目无关的资讯卡片
- 通用绘图、无关扩展功能入口
- 非必要登录、会员、升级等商业化入口
- 与科研综述任务无关的多余菜单项

### 5.4 首页核心交互区
首页中部保留一个统一输入区，但不再作为普通聊天框使用，而是作为“任务发起入口”。

用户进入系统后，可以通过该区域选择三类核心任务流：

- 文献检索
- 论文研读
- 综述写作

系统应根据不同任务流切换不同的页面内容、输入提示、内置 skill 和结果展示形式。

## 6. 核心任务流设计

### 6.1 任务流一：文献检索
目标是帮助用户围绕研究主题完成候选文献收集与初步筛选。

任务流步骤：
1. 用户选择项目或新建项目
2. 输入研究主题、关键词或检索要求
3. 系统调用检索流程与相关 skill
4. 页面展示候选文献列表
5. 用户筛选、标记并导入项目
6. 系统保存元数据、BibTeX 和下载任务状态

页面输出结果应包括：
- 候选文献列表
- 基础元数据
- 筛选状态
- 导入按钮
- PDF 下载状态

### 6.2 任务流二：论文研读
目标是帮助用户围绕已导入论文形成结构化理解，而不是只生成一段泛泛总结。

任务流步骤：
1. 用户从项目中选择一篇或多篇论文
2. 系统读取本地 PDF、元数据和笔记上下文
3. 调用研读类 skill
4. 输出结构化研读结果
5. 用户确认、修改并保存

页面输出结果应包括：
- 论文基本信息
- PDF 预览或打开入口
- 摘要与关键词
- 研究问题
- 方法概述
- 数据集或实验设置
- 结论与局限
- 用户笔记区

### 6.3 任务流三：综述写作
目标是基于已筛选和已研读文献生成综述准备材料，重点是提纲、分类和结构，而不是直接产出整篇论文。

任务流步骤：
1. 用户选择当前项目中的目标文献集合
2. 系统读取已沉淀的结构化文献数据
3. 调用综述写作类 skill
4. 生成提纲、主题分类或研究脉络
5. 用户调整后保存为项目成果

页面输出结果应包括：
- 综述提纲
- 一级与二级结构
- 主题分类结果
- 支撑文献列表
- 用户修改区

## 7. 页面信息架构

### 7.1 页面清单
- 页面 P1：项目首页
- 页面 P2：文献检索页
- 页面 P3：项目文献库页
- 页面 P4：论文详情/研读页
- 页面 P5：综述写作页
- 页面 P6：历史任务记录页

### 7.2 页面功能说明

#### P1 项目首页
功能：
- 新建项目
- 打开已有项目
- 进入三类核心任务流
- 查看最近任务

#### P2 文献检索页
功能：
- 输入研究主题或检索式
- 展示检索结果
- 筛选结果
- 批量导入项目
- 批量下载 PDF

#### P3 项目文献库页
功能：
- 查看项目内所有文献
- 按状态、标签、年份筛选
- 查看 BibTeX、PDF、备注状态
- 进入单篇研读页

#### P4 论文详情/研读页
功能：
- 查看论文元数据
- 查看 PDF 关联状态
- 查看或生成结构化研读结果
- 编辑用户笔记
- 保存研读结果

#### P5 综述写作页
功能：
- 选择纳入综述的文献
- 生成提纲
- 展示主题分类和支撑文献
- 编辑并保存结果

#### P6 历史任务记录页
功能：
- 查看历史检索任务
- 查看历史研读任务
- 查看历史提纲生成任务
- 重新打开或复用任务结果

## 9. 功能需求与验收标准

### 9.1 项目管理

| 需求编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-01 | 系统应支持创建研究主题项目。 | P0 | 用户输入项目名称后，系统成功创建项目，并在本地生成对应目录与初始化数据。 |
| R-02 | 系统应支持查看和切换已有项目。 | P0 | 用户可在项目列表中看到已有项目，并能进入任一项目继续工作。 |
| R-03 | 系统应在项目层面隔离数据。 | P0 | 不同项目的文献、笔记、提纲和任务结果互不混淆。 |

### 9.2 文献检索

| 需求编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-04 | 系统应提供文献检索入口。 | P0 | 用户在检索页输入研究主题或关键词后，可以发起检索任务。 |
| R-05 | 系统应展示候选文献结果。 | P0 | 检索结果至少展示标题、作者、年份、来源链接等信息。 |
| R-06 | 系统应支持将文献导入项目。 | P0 | 用户点击导入后，所选文献出现在当前项目文献库中。 |
| R-07 | 系统应支持对检索结果进行筛选。 | P1 | 用户可基于年份、来源或状态对结果进行筛选。 |
| R-08 | 系统应支持 PDF 下载。 | P1 | 用户对文献执行下载后，系统能够记录下载结果、本地路径和状态。 |

### 9.3 项目文献库与论文研读

| 需求编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-09 | 系统应提供项目文献库页面。 | P0 | 用户进入项目后可以看到当前项目下的文献列表。 |
| R-10 | 系统应支持文献状态管理。 | P0 | 用户可将文献设置为候选、已读、纳入综述等状态，且状态可持久保存。 |
| R-11 | 系统应支持文献标签和备注编辑。 | P1 | 用户编辑标签和备注后，刷新页面或重启系统后仍然可见。 |
| R-12 | 系统应支持 BibTeX 保存与导出。 | P1 | 用户可查看单篇 BibTeX，并导出项目级 BibTeX 文件。 |
| R-13 | 系统应提供论文详情/研读页。 | P0 | 用户点击文献后可进入详情页查看元数据、PDF 状态和笔记区。 |
| R-14 | 系统应支持结构化研读结果生成。 | P1 | 用户触发研读任务后，页面可展示研究问题、方法、结论等结构化内容。 |
| R-15 | 系统应支持保存研读结果。 | P1 | 用户确认或编辑后，结构化研读内容能够保存在当前项目中。 |

### 9.4 综述写作

| 需求编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-16 | 系统应提供综述写作入口。 | P0 | 用户可从首页或项目页进入综述写作页面。 |
| R-17 | 系统应支持基于项目文献生成提纲。 | P0 | 用户选择文献后，系统能够生成包含一级、二级结构的综述提纲。 |
| R-18 | 系统应展示提纲对应的支撑文献。 | P1 | 提纲页面能够显示相关条目所依赖的文献列表或引用来源。 |
| R-19 | 系统应支持用户编辑和保存提纲。 | P1 | 用户可修改提纲内容，并将结果保存为项目成果。 |

### 9.5 AI 工作流封装

| 需求编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-20 | 系统应将核心科研任务封装为固定任务流。 | P0 | 首页明确提供“文献检索”“论文研读”“综述写作”三类入口，而不是仅提供通用聊天框。 |
| R-21 | 系统应基于当前项目上下文调用 Codex。 | P0 | AI 生成内容默认关联当前项目的数据，不同项目之间不会串用上下文。 |
| R-22 | 系统应为不同任务流配置不同的内置 skill 或处理模板。 | P1 | 文献检索、论文研读、综述写作页面的输入提示、处理逻辑和输出样式存在明显差异。 |
| R-23 | 系统应将 AI 结果沉淀为项目资产。 | P1 | 生成的提纲、研读结果和文献整理结果能够保存并再次查看。 |

### 9.6 界面与体验

| 需求编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-24 | 系统应采用精简导航结构。 | P0 | 页面中不出现与当前课程目标无关的推荐、会员、绘图或商业化入口。 |
| R-25 | 系统应通过统一 Web 界面完成核心操作。 | P0 | 项目创建、检索、导入、研读、提纲生成等核心功能均可通过 Web 页面操作完成。 |
| R-26 | 系统应保留历史任务记录。 | P2 | 用户可以查看部分历史任务结果，并重新进入相应结果页面。 |

## 10. MVP 范围建议

### 10.1 必须完成
- 项目创建与切换
- 三类核心任务流入口
- 文献检索结果展示与导入
- 项目文献库
- 文献状态管理
- 论文详情页
- 综述提纲生成
- Codex 基于项目上下文调用
- 精简版 Web 界面

### 10.2 应争取完成
- PDF 下载
- BibTeX 导出
- 结构化研读结果
- 提纲保存
- 标签与备注

### 10.3 可延期功能
- 历史任务复用
- 更复杂的文献分类与聚类
- 更多辅助写作结果展示

## 11. 结论
本系统的核心不是做一个通用 AI 聊天网页，而是基于 Codex 封装出一个面向科研综述场景的本地 Web 工作台。其关键设计点在于：界面做减法、任务流做聚焦、AI 调用做约束、结果沉淀做结构化，从而让系统真正服务于研究生和个人研究者的文献综述工作。
